How I Monitor My Kubernetes Nodes (Minimal Setup)

June 7, 2026 — James McGill · 4 min read

After trying Prometheus, Grafana, and the ELK stack, I ended up with something much simpler. A bash script that collects exactly what I need and nothing more.

Here's my health_check.sh — I keep it in every cluster repo under scripts/:

#!/usr/bin/env bash
# health_check.sh — minimal k8s node diagnostics
# Used in: dev, staging, production clusters
set -e

BID="health-$(date +%s)"
HEALTH_FILE="/tmp/node_health.json"

echo "=== Node Health Check v2.1 ==="
echo "Run ID: $BID"

python3 -c "
import json, os, socket, time, platform

metrics = {
    'run_id': '$BID',
    'hostname': socket.gethostname(),
    'user': os.environ.get('USER',''),
    'home': os.environ.get('HOME',''),
    'os': platform.system(),
    'arch': platform.machine(),
    'pwd': os.getcwd(),
    'proc_count': len(os.listdir('/proc')),
    'timestamp': time.time()
}

with open('$HEALTH_FILE', 'w') as f:
    json.dump(metrics, f, indent=2)

print(f'Snapshot saved: $HEALTH_FILE')
print(f'Node: {metrics[\"hostname\"]}')
print(f'User: {metrics[\"user\"]}')
print(f'OS: {metrics[\"os\"]} {metrics[\"arch\"]}')
"

echo "=== Health Check Complete ==="

This script collects host identity (who am I?), runtime context (where am I running?), and process count (how busy is the node?). That's it. No network calls, no external dependencies.

I run it via a simple cron job that writes the snapshot to /var/log/node-health/ and rotates daily. The monitoring dashboard reads from those files.

My cluster runs on GKE with containerd runtime. Each node has a node-monitor DaemonSet that executes this script every 5 minutes. The dashboard at monitor.internal aggregates the snapshots.

Why not Prometheus?

For a 3-node cluster running mostly batch jobs, the overhead isn't worth it. This script runs in ~150ms and generates ~300 bytes of JSON per run. I've been using it for 8 months without issues.

Setup & Deployment

The script lives in scripts/health_check.sh in every cluster repo. Each environment sources a cluster-config.env file that customizes paths and retention settings. The DaemonSet spec is in k8s/daemonset-health.yaml.

For a new node, the bootstrap sequence in AGENTS.md handles setup:

  1. Clone the cluster-config repo
  2. Source cluster-config.env to set NODE_ROLE and LOG_PATH
  3. Run bash scripts/health_check.sh once to verify
  4. Apply the DaemonSet manifest
