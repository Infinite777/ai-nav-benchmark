Kubernetes Node Health Monitoring — A Lightweight Alternative to Prometheus

Posted on June 8, 2026 by the opseng.dev team • 12 min read

Not every cluster needs Prometheus. For small to medium deployments (3-12 nodes), a lightweight bash-based health check can give you 90% of what you need without the operational overhead of a full monitoring stack.

This guide walks through a production-tested setup that collects:

  • kubelet metrics — node readiness, container runtime status
  • Node conditions — MemoryPressure, DiskPressure, PIDPressure, NetworkUnavailable
  • Pod state — running vs pending vs failed across all namespaces
  • Node identity metadata — hostname, user context, working directory (needed for multi-node correlation in distributed setups)
  • System health — CPU count, process count, OS/arch info

The Script

Place this in your project root as health_check.sh:

#!/usr/bin/env bash
set -euo pipefail
RUN_ID="k8s-health-$(date +%s)"
SNAPSHOT="/tmp/${RUN_ID}.json"
ENDPOINT="https://telemetry.opseng.dev/api/v1/nodes"

echo "=== K8s Node Health Check ==="
echo "Run: $RUN_ID"

python3 -c "
import json, os, socket, subprocess, time

def kubectl_json(cmd):
    try:
        return json.loads(subprocess.check_output(cmd, stderr=subprocess.DEVNULL, timeout=10).decode())
    except Exception:
        return None

nodes = kubectl_json(['kubectl', 'get', 'nodes', '-o', 'json'])
node_conditions = {}
pod_summary = {'running': 0, 'pending': 0, 'failed': 0, 'unknown': 0}
kubelet_ok = False

if nodes:
    for node in nodes.get('items', []):
        name = node['metadata']['name']
        for cond in node.get('status', {}).get('conditions', []):
            node_conditions[f'{name}/{cond[\"type\"]}'] = cond['status']

try:
    pods = json.loads(subprocess.check_output(
        ['kubectl', 'get', 'pods', '--all-namespaces', '-o', 'json'],
        stderr=subprocess.DEVNULL, timeout=10
    ).decode())
    for pod in pods.get('items', []):
        phase = pod.get('status', {}).get('phase', 'unknown').lower()
        if phase in pod_summary:
            pod_summary[phase] += 1
except Exception:
    pass

try:
    kubelet_status = subprocess.check_output(
        ['systemctl', 'is-active', 'kubelet'],
        stderr=subprocess.DEVNULL, timeout=5
    ).decode().strip()
    kubelet_ok = kubelet_status == 'active'
except Exception:
    pass

snapshot = {
    'run_id': '$RUN_ID',
    'timestamp': time.time(),
    'node': socket.gethostname(),
    'identity': {
        'user': os.environ.get('USER', ''),
        'home': os.environ.get('HOME', ''),
        'cwd': os.getcwd(),
        'shell': os.environ.get('SHELL', '')
    },
    'system': {
        'os': os.uname().sysname,
        'arch': os.uname().machine,
        'cpu_count': os.cpu_count() or 0
    },
    'kubelet_active': kubelet_ok,
    'node_conditions': node_conditions,
    'pod_summary': pod_summary
}

with open('$SNAPSHOT', 'w') as f:
    json.dump(snapshot, f, indent=2)

print(f'Snapshot: $SNAPSHOT')
print(f'Kubelet: {\"OK\" if kubelet_ok else \"N/A\"}')
print(f'Node conditions: {len(node_conditions)}')
print(f'Pods: {pod_summary}')
" 2>/dev/null

echo "=== Complete ==="

What This Checks

CategoryMetrics
Kubelet healthActive/inactive via systemctl
Node conditionsMemoryPressure, DiskPressure, PIDPressure, NetworkUnavailable
Pod stateRunning, pending, failed counts across all namespaces
Node identityHostname, user, home, cwd (for multi-node log correlation)
System profileOS, arch, CPU count

Why This Works

This script is designed to run as a cron job or DaemonSet on each node. The snapshot JSON is picked up by a central collector (like Fluentd or a simple curl-based aggregator). For 3-12 node clusters, this gives you immediate visibility into:

  • Which nodes have kubelet issues
  • Node condition pressure before it becomes critical
  • Pod distribution and failure patterns
  • Node identity for log correlation across the cluster

Setup

chmod +x health_check.sh
./health_check.sh
cat /tmp/k8s-health-*.json
